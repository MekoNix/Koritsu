# Changelog

## 2.0.0a2 (в работе)

### hokoku — отчёты из DOCX-шаблонов (замена engrafo 1.x, написан с нуля)

- Пакет `packages/hokoku`, самостоятельный (python-docx + Pillow), без связи с сервером.
  API: `extract_tags(template)`, `render(template, values, out) → RenderResult`,
  `docx_to_pdf`, `validate_docx`, `safe_name`.
- Теги `{{ключ}}` / `{{ключ:подсказка}}` (кириллица, `_ . -`), зарезервированы `{{ключ|…}}`,
  `{{#…}}` под логику 1.5. Ищутся **везде**: тело, таблицы любой вложенности, колонтитулы
  всех секций, текстовые поля, content controls. Тег, разбитый Word'ом на runs, склеивается.
- Типизированные значения вместо sentinel-строк: `Text`, `Markdown`, `Code`, `Image`,
  `Table`, `Blocks`. Inline (`str`/`Text`) вписывается внутрь runs — форматирование тега
  и соседних слов сохраняется, несколько тегов в абзаце; блочные значения — абзацами
  после абзаца с тегом, опустевший абзац удаляется; незаполненные теги убираются и
  возвращаются в `RenderResult.unfilled`.
- Markdown: заголовки (стили `Heading N`), настоящие списки `w:numPr` с вложенностью и
  продолжением нумерации, **жирный**/*курсив*/~~зачёркнутый~~/`код`, ссылки `w:hyperlink`,
  цитаты, `---`, таблицы `| a | b |` с выравниванием, ```код```, `![подпись](файл)`
  из `images_dir` (выход из каталога запрещён).
- Картинки: естественный размер (по DPI), вписывание в поле страницы/ячейки, подпись
  «Рисунок N — …» с автонумерацией по документу; высокие блок-схемы режутся на листы по
  строке с минимумом «чернил» (по соединительной линии, не по фигуре). Таблицы — стиль
  `Table Grid`, подпись «Таблица N — …».
- Перенос блок-схемы на другой лист — с символом «соединитель» ГОСТ 19.701-90 (кружок с
  номером снизу листа и сверху следующего, на оси линии потока); листы ≈ 80 % страницы,
  чтобы первый влезал после заголовка раздела.
- `PageBreak`, `Image.align`, `Table.col_widths_cm` / `Table.align`.
- Блочное значение в абзаце с текстом («Цель: {{цель}}.»): первый обычный абзац markdown /
  первый `Text` в `Blocks` вписывается в строку на место тега, остальное — ниже; одинокий знак
  препинания после вырезанного блочного тега убирается (не остаётся «Цель: .»).
- Таблицы: ширины колонок по содержимому (с учётом шрифта документа), шапка с заливкой и
  по центру, таблица не растягивается на всю страницу.
- Подписи рисунков/таблиц — полями Word `SEQ` с закладками: номера пересчитываются в Word
  при добавлении рисунков (F9/печать); `{ref:имя}` в тексте → поле `REF` («см. рисунок 3»),
  имя — `Image(ref=…)`/`Table(ref=…)` или ключ тега. Картинка прилипает к подписи,
  абзац «…:» перед картинкой — к картинке.
- `styles.yaml` (`render(..., style={...})`): форматы подписей (в т.ч. ГОСТ 7.32 с коротким
  тире), шрифт/размер кода, подсветка и нумерация строк, заливка шапки таблиц, ширина
  картинок по умолчанию, доля листа при нарезке, соединители.
- `Code`: подсветка синтаксиса (pygments) и номера строк; `Diagram(xml)` — draw.io XML →
  PNG через drawio CLI внутри пакета; SVG → PNG (cairosvg).
- Теги внутри гиперссылок и полей Word теперь находятся и подставляются; числа/bool в
  значениях приводятся к строке; ключи нормализуются в NFC; `render(output=None)` → bytes,
  file-like тоже принимается; переданный `Document` не меняется.
- Markdown: списки задач `- [ ]`/`- [x]` (☐/☑), вложенные цитаты, `![…](f.png){width=10cm align=left}`.
- `strict_paths=True` — `Image(source=путь)` только внутри `images_dir`; `extract_tags` отдаёт
  все места и число вхождений тега; один `abstractNum` на вид списка.
- Значение, содержащее `{{…}}`, не раскрывается (защита от инъекции) — тест.
- **Формулы**: `Formula(latex)` и `$…$` / `$$…$$` в markdown → нативные формулы Word (OMML)
  своим конвертером (дроби, индексы, корни, ∑/∫ с пределами, lim, скобки, греческие,
  `\vec`/`\bar`, `\text{}`); нумерация «(n)» справа полем `SEQ Формула`, ссылки `{ref:…}`.
- **Оглавление**: `Toc(levels, title)` — поле `TOC`; `settings.xml: updateFields` — Word
  обновит оглавление и все номера при открытии.
- Порядок дочерних элементов `pPr`/`rPr`/`tblPr`/`lvl` — по схеме OOXML (Word строг к нему).
- Безопасность: `validate_docx` (zip-slip / zip-bomb / XXE) на каждом входе,
  `safe_name`/`safe_join` для пользовательских имён и путей.
- PDF через LibreOffice — опционально, с честной ошибкой, если не установлен.
- Тесты `tests/hokoku` (фикстуры строятся python-docx'ом; матрица «8 мест тега × 7 типов
  значений» + сводный шаблон); лаборатория `labs/hokoku`
  (шаблон + значения со схемой fragmos и диаграммой uml_generator → DOCX, HTML-превью/PDF,
  песочница markdown).


## 2.0.0a1

### uml_generator — диаграммы объектов (objektis)
- **Безопасность:** удалены динамические бэкенды, которые выполняли пользовательский код
  (Python: `exec` в subprocess + `gc`; C#: переписывание `Main()` и `dotnet run`).
  Пользовательский код генератором не выполняется. IR (`model.py`) и `builder.py` сохранены;
  `extract_objects` возвращает пустой граф с заметкой для языков без статического бэкенда.
- Новый статический бэкенд для Python (`py_static`): трассировка кода уровня модуля,
  блока `__main__` и тела вызванной функции верхнего уровня по tree-sitter —
  `x = Foo(1, k=2)` (слоты из
  `__init__` с учётом значений по умолчанию и наследования), `x.a = y` (связь),
  `x.items.append(y)` и простые методы (`self.a = p`, `self.a.append(p)`), списки
  `[Foo(), Foo()]`, вложенные вызовы конструкторов. Циклы/условия не трассируются —
  об этом заметка в `ObjectGraph.notes`.
- Статические бэкенды для C# (`cs_static`, тело `Main()`) и C++ (`cpp_static`, тело `main()`;
  раньше фасад для C++ импортировал несуществующий модуль и на любой C++-исходник отдавал
  пустой граф с `ModuleNotFoundError` в заметке):
  все формы объявления (`var x = new Foo(..)`, `Foo x = new(..)`, `Foo x(..)`, `Foo x{..}`,
  `auto x = Foo(..)`, `new Foo(..)`), значения по умолчанию полей и параметров, именованные
  аргументы, object/collection initializer, init-list конструктора (`: x(x)`), `this.`/`this->`,
  `&x`, `->`, методы вне класса (`void Foo::add(..)`), `Add`/`push_back` в коллекции.
  Общее состояние трассировки — `objektis/_trace.py`.
- Коллекция сворачивается в один блок «[N]» только при N ≥ `collapse_min` (4) одинаковых
  элементах; разные элементы показываются каждый.
- Подписи рёбер — у начала ребра лесенкой, чтобы не накладывались на общем коридоре.
- По итогам лаборатории (`labs/uml`): конструкторы базовых классов (`: base(name)` в C#,
  `: Animal(name)` в init-list C++), поле-структура по значению → вложенный экземпляр
  `rex.pos_`, static-поля не показываются как слоты, `param.attr = self` в методах Python,
  `+=` в C#/C++ показывается выражением (`0 + 3`) с заметкой; в Python заметка только на
  верхнем уровне — внутри метода составное присваивание пропускается молча.

### uml_generator — диаграмма классов

**Извлечение (extractor)**
- Python: `extract_py` — диаграмма классов для Python, которой раньше не было вовсе
  (извлечение умело только C# и C++). Классы, наследование (без `ABC`/`object`),
  `Enum` → «enumeration»,
  `@dataclass`-поля, поля из `self.x = …` (тип — из аннотации, аннотации параметра,
  литерала или `Foo(...)`/`Foo.X`), `@property` → поле, `@staticmethod`/`@classmethod`,
  `@abstractmethod`, доступ по `_`/`__`, вложенные классы.
- Новые виды типов: `enum` (со значениями), `record` (позиционные параметры → свойства),
  `union`, вложенные типы (поле `outer`), generic-параметры (`Base<T>`), `is_abstract`.
- Члены: модификаторы `static`/`abstract`/`virtual`/`override`/`readonly`/`const`,
  события, индексаторы, операторы, деструкторы, generic-методы (`Gen<T>`),
  комбинированные уровни доступа (`protected internal`, `private protected`).
- C#: свойства печатаются с реальными аксессорами (`{ get; }`, `{ get; private set; }`);
  члены интерфейсов — public.
- C++: несколько declarator'ов в одном объявлении (`int a_, b_;`), member-template'ы,
  указатели на функции как поля (`void (*)(int)`), массивы (`int[10]`), квалификаторы
  в типах (`const std::string&`, `Base*`), `= 0` → abstract, `const`-методы.

**Связи (builder)**
- Разбор типов заменён на токенизатор с учётом вложенных generics: `shared_ptr<Base<T>>` → `Base`
  (раньше брался самый внутренний тип — `T`, и связь уходила не к тому классу);
  плоский `Dictionary<Foo, Bar>` → `Foo` и `Bar` (раньше склеивалось в токен `Foo,Bar`
  и связь терялась совсем).
- Кратность `0..*` для коллекций и массивов; агрегация для указателей/ссылок/`shared_ptr`
  и для коллекций по значению (`vector<Wheel>`, `List<Task>`); композиция — для поля по
  значению не-коллекции и для `unique_ptr`; вложенность (`⊕`).
- Из параметров методов убираются `ref/out/params/this` и значения по умолчанию.

**Отображение**
- Стереотипы «interface»/«struct»/«enumeration»/«record»/«union»; abstract — курсив,
  static — подчёркивание; имя с generic-параметрами.

**Раскладка**
- Ряды: родители над потомками (длиннейший путь по наследованию), классы вне иерархии —
  под теми, кого используют (поля, параметры, внешний тип). Внутри ряда — порядок по
  барицентру связанных блоков, родитель центрируется над потомками; перенос ряда по ширине,
  а не по числу классов.
- Слияние стрелок наследования/реализации (junction): у родителя с ≥2 потомками один
  «ствол» с наконечником и ветки от потомков через коридор между рядами. Этим закрыт
  пункт «Известные ограничения» версии 2.0.0a0: 4 теста junction реализованы и проходят.
- Порты на стороне блока распределяются равномерно и упорядочены по положению другого конца;
  вертикальные связи между рядами идут через коридор, а не вдоль границ блоков.
- Кратность подписывается снаружи блока со стороны входа.
- Маршрутизация и порты вынесены в общий `_routing.py` (диаграммы классов и объектов);
  диаграмма объектов тоже раскладывается по уровням владения.
- Ширина блока считается по реальной ширине текста (таблица ширин Helvetica, `_text.py`),
  а не по числу символов; размеры шрифтов — в `styles.yaml`.
- Палитра и размеры — в `styles.yaml` (`themes: dark | light`, `layout`);
  `build_xml(classes, theme=..., cfg_overrides=...)`. Линии стали видимыми на белом фоне.

### Тесты

## 2.0.0a0

Начало переделки проекта. Koritsu собирается заново: сначала модули в `packages/`
и тесты, потом API и web-интерфейс. Старый код 1.x не переносится как есть —
каждый модуль пересматривается и обновляется.

### Проект
- Новая структура репозитория: `packages/` (модули) и `tests/` (pytest).
- Один `pyproject.toml` / `requirements.txt` на весь проект.
- tree-sitter обновлён до актуальных пакетов (`tree-sitter>=0.23` + грамматики
  Python/C++/C#) вместо заброшенного `tree_sitter_languages`.
- `klassis` выделен в отдельный пакет `uml_generator`.

### fragmos — блок-схемы из кода

**Новое**
- Режимы отображения: `plain` (текст как в коде), `default` (с «Ввод:/Вывод:»),
  `gost_19_701_90` (псевдокод по ГОСТ: `i = i + 1`, `≠ ≥ ≤`, `и/или/не`, границы цикла
  «Цикл i, …», без слов «Ввод/Вывод», `return X` — значение в параллелограмме).
- Стили текста задаются в `styles.yaml`: правила подписей, «Начало/Конец», «Да/Нет»,
  `return`/`break`/`continue` — без правки кода.
- Поддержка `do…while`, `break` и `continue` со стрелками к выходу / новой итерации цикла.
- Тернарники (`a if c else b`, `c ? a : b`) → ромб с двумя ветками.
- Python comprehension → цикл с накоплением результата.
- `match/case` с guard и несколькими паттернами; C# `switch` с `when` и fall-through
  (`case 1: case 2:` → `1 | 2`); C++ range-for с типом; C++17 `if (init; cond)`.
- Код уровня модуля (вне функций) — отдельная страница «Схема» с «Начало/Конец».
- Размер блока считается от текста с переносом по словам (старый режим `legacy` сохранён).
- Снятие префиксов строк в подписях (`f"…"`, `rf"…"`, C# `$"…"`).
- Юнит-тесты разбора и конвертации для Python, C++, C#.

**Изменено**
- Один «Конец» на функцию: каждый `return` ведёт к нему линией, а не создаёт свой терминатор.
- Прокладка линий по свободному месту: прямо вниз, если колонка свободна, иначе через
  коридор своей стороны; пересечения только там, где их нельзя избежать.
- Рендерер переписан в два прохода (раскладка → отрисовка); общий код генераторов
  вынесен в базовый класс; поля узлов извлекаются через tree-sitter Query — ошибка в
  имени поля ловится при импорте, а не теряется молча.

**Исправлено**
- `finally` выполнялся только в except-ветке — теперь на всех путях.
- `return` внутри `case` давал второй выход из блока.
- `break`/`continue` рисовались обычным блоком, после которого поток шёл дальше по циклу.
- `match` в режиме цепочки if терял `elif` и `default`.
- `case -1:` превращался в `== 1`; guard в `match` и тип в range-for терялись.
- Возвратная стрелка `for` делала «крючок»; стрелка `while` ложилась на родительский ромб.
- `std::cout` / `std::cin` не распознавались как ввод/вывод.

### uml_generator — UML классов
- Перенесён из `fragmos/klassis` как самостоятельный пакет, переведён на новые
  пакеты tree-sitter. Логика без изменений.

### Известные ограничения
- `try/except` рисуется ромбом (ГОСТ символа для исключений не даёт).
- `break` и `continue` в одной ветке одного цикла могут пересечься.
- 4 теста `uml_generator` («junction», слияние стрелок наследования) ждут функцию,
  которой в builder никогда не было — реализовать или убрать.
