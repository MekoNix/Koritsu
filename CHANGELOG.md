## 2.0.0a2.8 (в работе) — правки трёх модулей, вторая волна

Три агента по пакетам плюс проверка возможностей глазами. Тесты 217 → 245 (плюс 24 subtests).
LLM-часть по-прежнему не начата: только правки и оптимизация.

### hokoku

- **Шаблон с макросами VBA отклоняется.** Дыра проверена: обычный `.docx`, к которому подложили
  `word/vbaProject.bin` со связью, проходил валидацию, и блоб **байт в байт оказывался в
  собранном отчёте**, который студент понесёт на кафедру. Настоящий `.docm` при этом ронял
  голый `ValueError` из python-docx мимо нашего контракта. Вырезать макрос нельзя по существу —
  пользователь получил бы документ, отличающийся от проверенного в Word, — поэтому шаблон
  отклоняется целиком. `[Content_Types].xml` и связи читаются целиком до потолка: `Override`
  с vbaProject прячется и в конце длинного файла.
- **Внешние ссылки шаблона режутся из результата**: `attachedTemplate`, OLE-объекты,
  поддокументы. Сам шаблон из-за них не отклоняется — `attachedTemplate` есть у любого
  документа, сделанного из кафедрального `.dotx`.
- **Заглушка оглавления больше не печатается в PDF.** LibreOffice поле TOC не разворачивает и
  печатал кэш как обычный текст: в сданном PDF на месте оглавления стояла фраза «Оглавление
  обновится при открытии документа». Механизм TOC не тронут — выбор «UNO против своей сборки»
  остаётся открытым.
- **Предел рисовался как общая дробь.** `\lim_{x \to 0} \frac{\sin x}{x}` выходил в PDF как
  «(lim sin x)/x», то есть формула читалась неверно. OMML был структурно верен, поэтому тесты
  молчали; поймано проверкой страниц глазами. Предел теперь пишется функцией
  (`m:func` с именем-пределом и телом внутри), как того и ждут Word и LibreOffice.
- Таймаут drawio задаётся снаружи (`render(..., drawio_timeout=)`), а срыв таймаута приходит
  нашей ошибкой, а не голым `subprocess.TimeoutExpired`.
- Подпись «Таблица N — …» получает отступ своей таблицы (тег в пункте списка).

### fragmos

- C# `lock (this)` терял заголовок: `this` в грамматике — безымянный узел, перебор именованных
  детей его не видел. Заодно доезжают `lock (GetLock())` и `lock (items[i])`.
- C++ объявление без инициализатора (`std::vector<int> v;`) не рисовалось вовсе — в схему
  попадали только объявления с присваиванием.
- Подпись цикла выдавала вызов функции за переменную цикла: `do … while (next(i))` в режиме
  ГОСТ давало «Цикл next, пока next(i)», а `while (!done)` — «Цикл не». Переменная ищется
  в исходном условии и только если это идентификатор; иначе «Цикл, пока …».
- Попутно: ключи `yes`/`no` в `styles.yaml` YAML читал как `True`/`False`.

### uml_generator

- **Связи искались по короткому имени.** Два класса `Prim` из разных namespace — ребро уходило
  в первый одноимённый, а поле `N1.Prim` внутри `N2.Prim` отбрасывалось как ссылка на себя.
  В extractor'е появилась область видимости (`scope`, `uid`): разобраны `namespace a::b`
  и безымянный namespace C++, `namespace N;` до конца файла и вложенные namespace C#;
  `partial` склеивается только внутри своей области. Поиск связей на 200 классах — 11.7 мс.
- **Взаимная ссылка полей-объектов уводила в рекурсию**: `class Order { Customer& buyer; }` и
  наоборот давали 993 фантомных объекта и заметку «трассировка прервана» вместо схемы.
  Теперь цикл обрывается с внятной заметкой, а цепочка без цикла разворачивается целиком.
- **Тема `css`: цвета ролями** (`var(--node-fill,#ffffff)` и ещё одиннадцать). В SVG роли
  выходят наружу дословно — интерфейс перекрашивает схему CSS'ом без перегенерации, — а PNG
  темы `css` побайтно совпадает с PNG темы `light`, то есть отчёт получает светлую схему без
  подстановки. `light`/`dark` и умолчание не менялись.

### Проверка возможностей глазами

Новая лаборатория (`labs/check`): 67 случаев по всем возможностям трёх пакетов — исходник,
«что должно получиться» словами и настоящий артефакт (страница PDF, схема, собранный DOCX),
плюс страница с пометками «да / нет». Она и нашла дефект с пределом, которого не видел ни один
автотест, и подтвердила незакрытый пункт «текст вылезает за рамку блока» в uml.

## 2.0.0a2.6 (в работе) — правки трёх модулей

Три агента, по одному на пакет, каждый дефект воспроизведён до правки и после.
LLM-часть не начата сознательно: сейчас только правки и оптимизация. Тесты 163 → 213
(плюс 8 subtests); раскладка fragmos покрыта тестами впервые.

### hokoku — по следам проектной записки и её ревизии

- **Таблица собиралась квадратично.** `tbl.cell(r, c)` каждый раз строил всю матрицу ячеек
  заново (учёт `gridSpan`/`vMerge`), 98 % времени рендера уходило туда: 400 строк —
  **42 → 0.19 с**, 200 строк — 11 → 0.12 с; зависимость стала линейной. Матрица берётся
  один раз, вывод байт в байт прежний.
- **Значение с ключом, которого нет среди тегов, исчезало молча** — ни в `unfilled` (там
  только объявленные теги), ни в `errors`. Опечатка в ключе давала пустой тег и никакого
  объяснения. Появилось `RenderResult.unknown_keys`.
- **Битая формула собиралась молча**: `\frac{1}{` давал дробь с пустым знаменателем, а в
  отчёт уходили пустые скобки «(1)». Разбор стал строгим — незакрытая скобка, отсутствующий
  аргумент и окружения `\begin`/`\end` дают ошибку (`OmmlError` → `HokokuError`, а с
  `on_error="skip"` — запись в `errors`). Неизвестная команда по-прежнему идёт текстом.
- **Номер закладки был общим на процесс**: одинаковый вход давал разные файлы (мешает
  кэшировать и сравнивать), а два одновременных рендера могли разорвать пару
  `bookmarkStart`/`bookmarkEnd` — те самые закладки, на которых держатся `{ref:}`.
  Счётчик стал свой у документа.

### fragmos

- **Подписи не экранировались, а все стили фигур идут с `html=1`** — draw.io глотал `<n`
  как начало тега: `if i<n:` рисовалось как «i», `vector<int>` терял параметр. Самый дорогой
  дефект проекта: в блок-схеме условия и есть суть.
- **Диспетчер `_convert` не знал типа `process`** и возвращал пустой список, а генераторы
  порождают такой узел в девяти местах: `raise`, `del`, `yield`, `throw`, `goto`, `delete`,
  `co_yield`, `lock`, заголовок локальной функции. Всё это исчезало из схемы бесследно.
- Вложенные классы и функции терялись целиком. Попутно: python-функция в функции выдавала
  START/STOP внутрь тела родителя и резала его страницу пополам.
- `do { … } while (next(i))` давало условие `next(i` (`strip('()')` снимал все скобки);
  Python `for … else` клал тело `else` внутрь цикла; C++ range-for подписывался сырым
  «auto x : v».
- Метки `case` рисовались прямоугольниками «процесс», `default` подписывался `_` — теперь это
  подписи на линиях выхода из «решения». Попутно: ключи `yes`/`no` в `styles.yaml` YAML читал
  как `True`/`False`, то есть заданные в стиле подписи выходов не применялись вовсе.
- `break` и `continue` из одной ветки ложились на одну вертикаль; отладочные рамки `show_bbox`
  меняли маршруты рёбер, то есть отладочный флаг менял саму схему.
- Импорт fragmos перехватывал корневой логгер всего процесса (`drawpyo` зовёт
  `logging.basicConfig` при импорте).
- **Вывод стал воспроизводимым побайтно**: id диаграммы и ячеек были адресами объектов в
  памяти, `modified` — временем записи. Без этого нельзя ни кэшировать, ни сравнивать в тесте.
- Fall-through в `switch` реализован честно (дублирование тел), C# `goto case` подставляет
  копию тела цели. Раньше `case 3: break;` приклеивался к `default` как общий вход — схема
  утверждала, что при `x==3` выполнится тело `default`.

### uml_generator

- Квадратная скобка в типе больше не значит «массив» по всей строке: `Optional[Product]` и
  `Callable[[int], Product]` давали агрегацию «0..*».
- C# 9 top-level statements: без `Main()` объектный граф выходил пустым, хотя extractor
  работал. C# 12 `class Prim(int seed, string name)` давал два несуществующих свойства.
- Алиас `m = M(); y = m; t.owner = y` терял объект; рекурсивный метод давал `RecursionError`
  и пустой граф — теперь есть граница глубины, а частичный результат возвращается при любом
  обрыве.
- `self.a = self.b = 0` давало только «a», `self.x, self.y = 1, 2` — ничего.
- Одноимённые классы (`partial`, разные namespace) затирали друг друга: ячейки лежали одна на
  другой под общим id. Множественное наследование: ветка и одиночное ребро выходили из одной
  точки потомка. `const` у C++-метода стоял в типе возврата.
- Попутно: значения слотов диаграммы объектов экранировались один раз вместо двух — то же
  семейство, что главный дефект fragmos.

### hokoku

- **Ширины колонок, два механизма.** `w:tblGrid` оставался равномерным от python-docx, и
  LibreOffice в PDF смотрел на него, а не на `w:tcW`: колонки 1.04/13.17/1.04 см выходили как
  5.09/5.08/5.09 — расчёт пропадал именно в том формате, в котором сдают отчёт. Второй:
  при нехватке места раскладка ужимала колонки пропорционально и продавливала короткие ниже

- Картинка в ячейке без `w:tcW` (так таблицу пишет Word) бралась по ширине страницы: логотип

- Тег в текстовом поле внутри `mc:AlternateContent` обрабатывался дважды (копия лежит и в
  `Choice`, и в `Fallback`) — один тег давал два рисунка и сбитую нумерацию.
- `{ref:имя}` внутри подписи оставался литералом; таблица в пункте списка не получала

### Исправлено (каждое воспроизведено до правки)

- **Zip-бомба проходила проверку.** 1900 членов по 50 КБ нулей — архив 344 КБ, в памяти
  97 МБ: степень сжатия проверялась у каждого члена отдельно и только при сжатом размере
  от 1 КБ, а сумма укладывалась в лимит. Теперь размеры считаются распаковкой с потолком
  (заголовкам zip доверять нельзя), отдельно ограничен весь XML пакета (его целиком читает
  lxml), добавлена проверка сжатия по архиву целиком. Цена на обычном шаблоне — 2–3 мс.
- **Оператор внутри дроби терял тело.** `\frac{\sum_{i=1}^{n} x_i}{n}` давал в Word сумму
  с пустым местом, а `x_i` уезжал вбок: `_attach_bodies` разбирал только верхний уровень.
  Теперь спуск рекурсивный — то же и под корнем, и в скобках.
- **Картинку нельзя было вставить без подписи.** `caption=None` всё равно печатал

  а в колонтитулах нумерации нет никогда: логотип в шапке больше не «Рисунок 1»
  и не сдвигает нумерацию всего отчёта.
- **`{ref:имя}` в тексте самого шаблона** (не в значении) оставалась текстом в фигурных
  скобках и не попадала в `unresolved_refs` — теперь это такое же поле REF.
- **`unresolved_refs`** содержал служебное `_Ref_имя`, а `refs` — имя; теперь оба по имени.
- **Два блочных тега в одном абзаце** получали номер и закладку по ключу самого левого
  из них — теперь у каждого свой.
- **Одна битая картинка уносила весь отчёт.** `render(..., on_error="skip")` собирает
  что может, а беды складывает в `RenderResult.errors` как `{key, message}`;
  по умолчанию поведение прежнее (`"raise"`).

### Быстрее (замеры на одной машине, до → после)

- Поиск абзацев с тегами — один XPath на часть документа вместо разбора runs у каждого
  абзаца: `extract_tags` на шаблоне в 2030 абзацев **145 → 32 мс**, рендер **230 → 81 мс**.
- Словарь «имя стиля → id» на документ и запись стиля таблицы прямо в `w:tblStyle`:
  python-docx искал стиль по имени XPath'ом на каждый заголовок, пункт списка и таблицу —
  это была четверть времени. Рендер 30 markdown-тегов **225 → 133 мс**, отчёт из 90
  блоков **611 → 293 мс**.
- `drawio_to_png` кэшируется по хешу XML: повторный вызов **3.0 с → 0 с**; одна и та же
  схема в двух тегах больше не считается дважды. `cache=False` и `clear_png_cache()` — рядом.

### По следам аудита (agent, 2026-08-28)

- `validate_docx` больше не режет честный документ: 5000 одинаковых абзацев дают сжатие
  223:1, и порог 200 на член отклонял такую методичку как бомбу. Степень сжатия теперь
  проверяется у вложений (картинки так не сжимаются), а XML держится абсолютным потолком —
  он и есть то, что целиком читает lxml. Бомба из 1900 членов по-прежнему отклоняется.
- `validate_docx`: член с неподдерживаемым методом сжатия ронял `NotImplementedError`
  мимо `DocxValidationError` (привнесено проверкой распаковкой) — теперь метод сжатия
  проверяется явно, допускаются stored и deflate.
- `{ref:имя}` в ячейке таблицы-значения оставался с кэшем «?» и не попадал в
  `unresolved_refs`: ячейки пишет `ops.add_table` напрямую, мимо регистрации полей REF.
  Поля теперь ищутся во всём поддереве таблицы. Тот самый пункт из `status.md`, который
  на простом случае не воспроизводился, — условие в том, что ссылка приходит **внутри
  значения-таблицы**, а не стоит в шаблоне.
- `on_error="skip"` пропускал мимо себя чужие исключения: WEBP-картинку python-docx
  не знает и кидает `UnrecognizedImageError` — весь рендер падал при заявленном «собери
  что можешь». И хвост `Blocks` после битого элемента терялся молча. Оба случая закрыты.

### Удалено: нарезка картинок на листы

`Image.split_pages`, `Diagram.split_pages`, `images.split_tall` с соединителями и ключи
`image.sheet_fraction` / `image.connectors` — вырезаны. Резать готовый растр по «пустым»
строкам значит гадать: там, где линия потока идёт через весь лист, разрез рвёт фигуру,
а соединитель ГОСТ 19.701-90 рисуется поверх картинки, а не в схеме. Где рвать алгоритм,
знает только тот, кто его нарисовал, — эта работа уходит в fragmos (параметр разбиения,
многостраничный mxfile с соединителями в самой схеме).

Взамен в hokoku: **страницы mxfile — это листы одного рисунка.** `Diagram(xml)` рендерит
все страницы схемы, каждая идёт «Рисунок N (лист k из m)» с общим номером, общей закладкой
и полем SEQ с `\c`; `Diagram(xml, page=k)` — один лист, нумерация с 1. Раньше из
многостраничного mxfile бралась только первая страница, а `page` уходил в drawio как есть,
и тот при выходе за границу молча отдавал последнюю — теперь номер проверяется
(`images.count_pages`). Слишком высокая картинка просто вписывается в страницу.

Тестов было 150, стало 161; все зелёные.

## 2.0.0a2 (в работе)

### hokoku — отчёты из DOCX-шаблонов (замена engrafo 1.x, написан с нуля)

- Пакет `packages/hokoku`, самостоятельный (python-docx + Pillow), без связи с сервером.
  API: `extract_tags(template)`, `render(template, values, out) → RenderResult`,
  `docx_to_pdf`, `validate_docx`, `safe_name`.
- Теги `{{ключ}}` / `{{ключ:подсказка}}` (кириллица, `_ . -`), зарезервированы `{{ключ|…}}`,
  `{{#…}}` под логику 1.5. Ищутся **везде**: тело, таблицы любой вложенности, колонтитулы
  всех секций, текстовые поля, content controls. Тег, разбитый Word'ом на runs, склеивается.
- Типизированные значения вместо sentinel-строк: `Text`, `Markdown`, `Code`, `Image`,
  `Table`, `Blocks`. Inline (`str`/`Text`) вписывается внутрь runs — форматирование тега
  и соседних слов сохраняется, несколько тегов в абзаце; блочные значения — абзацами
  после абзаца с тегом, опустевший абзац удаляется; незаполненные теги убираются и
  возвращаются в `RenderResult.unfilled`.
- Markdown: заголовки (стили `Heading N`), настоящие списки `w:numPr` с вложенностью и
  продолжением нумерации, **жирный**/*курсив*/~~зачёркнутый~~/`код`, ссылки `w:hyperlink`,
  цитаты, `---`, таблицы `| a | b |` с выравниванием, ```код```, `![подпись](файл)`
  из `images_dir` (выход из каталога запрещён).
- Картинки: естественный размер (по DPI), вписывание в поле страницы/ячейки, подпись
  «Рисунок N — …» с автонумерацией по документу; высокие блок-схемы режутся на листы по
  строке с минимумом «чернил» (по соединительной линии, не по фигуре). Таблицы — стиль

## 2.0.0a1

### uml_generator — диаграммы объектов (objektis)
- **Безопасность:** удалены динамические бэкенды, которые выполняли пользовательский код
  (Python: `exec` в subprocess + `gc`; C#: переписывание `Main()` и `dotnet run`).
  Пользовательский код генератором не выполняется. IR (`model.py`) и `builder.py` сохранены;
  `extract_objects` возвращает пустой граф с заметкой для языков без статического бэкенда.
- Новый статический бэкенд для Python (`py_static`): трассировка кода уровня модуля,
  блока `__main__` и тела вызванной функции верхнего уровня по tree-sitter —
  `x = Foo(1, k=2)` (слоты из
  `__init__` с учётом значений по умолчанию и наследования), `x.a = y` (связь),
  `x.items.append(y)` и простые методы (`self.a = p`, `self.a.append(p)`), списки
  `[Foo(), Foo()]`, вложенные вызовы конструкторов. Циклы/условия не трассируются —
  об этом заметка в `ObjectGraph.notes`.
- Статические бэкенды для C# (`cs_static`, тело `Main()`) и C++ (`cpp_static`, тело `main()`;
  раньше фасад для C++ импортировал несуществующий модуль и на любой C++-исходник отдавал
  пустой граф с `ModuleNotFoundError` в заметке):
  все формы объявления (`var x = new Foo(..)`, `Foo x = new(..)`, `Foo x(..)`, `Foo x{..}`,
  `auto x = Foo(..)`, `new Foo(..)`), значения по умолчанию полей и параметров, именованные
  аргументы, object/collection initializer, init-list конструктора (`: x(x)`), `this.`/`this->`,
  `&x`, `->`, методы вне класса (`void Foo::add(..)`), `Add`/`push_back` в коллекции.
  Общее состояние трассировки — `objektis/_trace.py`.
- Коллекция сворачивается в один блок «[N]» только при N ≥ `collapse_min` (4) одинаковых
  элементах; разные элементы показываются каждый.
- Подписи рёбер — у начала ребра лесенкой, чтобы не накладывались на общем коридоре.
- По итогам лаборатории (`labs/uml`): конструкторы базовых классов (`: base(name)` в C#,
  `: Animal(name)` в init-list C++), поле-структура по значению → вложенный экземпляр
  `rex.pos_`, static-поля не показываются как слоты, `param.attr = self` в методах Python,
  `+=` в C#/C++ показывается выражением (`0 + 3`) с заметкой; в Python заметка только на
  верхнем уровне — внутри метода составное присваивание пропускается молча.

### uml_generator — диаграмма классов

**Извлечение (extractor)**
- Python: `extract_py` — диаграмма классов для Python, которой раньше не было вовсе
  (извлечение умело только C# и C++). Классы, наследование (без `ABC`/`object`),
  `Enum` → «enumeration»,
  `@dataclass`-поля, поля из `self.x = …` (тип — из аннотации, аннотации параметра,
  литерала или `Foo(...)`/`Foo.X`), `@property` → поле, `@staticmethod`/`@classmethod`,
  `@abstractmethod`, доступ по `_`/`__`, вложенные классы.
- Новые виды типов: `enum` (со значениями), `record` (позиционные параметры → свойства),
  `union`, вложенные типы (поле `outer`), generic-параметры (`Base<T>`), `is_abstract`.
- Члены: модификаторы `static`/`abstract`/`virtual`/`override`/`readonly`/`const`,
  события, индексаторы, операторы, деструкторы, generic-методы (`Gen<T>`),
  комбинированные уровни доступа (`protected internal`, `private protected`).
- C#: свойства печатаются с реальными аксессорами (`{ get; }`, `{ get; private set; }`);
  члены интерфейсов — public.
- C++: несколько declarator'ов в одном объявлении (`int a_, b_;`), member-template'ы,
  указатели на функции как поля (`void (*)(int)`), массивы (`int[10]`), квалификаторы
  в типах (`const std::string&`, `Base*`), `= 0` → abstract, `const`-методы.

**Связи (builder)**
- Разбор типов заменён на токенизатор с учётом вложенных generics: `shared_ptr<Base<T>>` → `Base`
  (раньше брался самый внутренний тип — `T`, и связь уходила не к тому классу);
  плоский `Dictionary<Foo, Bar>` → `Foo` и `Bar` (раньше склеивалось в токен `Foo,Bar`
  и связь терялась совсем).
- Кратность `0..*` для коллекций и массивов; агрегация для указателей/ссылок/`shared_ptr`
  и для коллекций по значению (`vector<Wheel>`, `List<Task>`); композиция — для поля по
  значению не-коллекции и для `unique_ptr`; вложенность (`⊕`).
- Из параметров методов убираются `ref/out/params/this` и значения по умолчанию.

**Отображение**
- Стереотипы «interface»/«struct»/«enumeration»/«record»/«union»; abstract — курсив,
  static — подчёркивание; имя с generic-параметрами.

**Раскладка**
- Ряды: родители над потомками (длиннейший путь по наследованию), классы вне иерархии —
  под теми, кого используют (поля, параметры, внешний тип). Внутри ряда — порядок по
  барицентру связанных блоков, родитель центрируется над потомками; перенос ряда по ширине,
  а не по числу классов.
- Слияние стрелок наследования/реализации (junction): у родителя с ≥2 потомками один
  «ствол» с наконечником и ветки от потомков через коридор между рядами. Этим закрыт
  пункт «Известные ограничения» версии 2.0.0a0: 4 теста junction реализованы и проходят.
- Порты на стороне блока распределяются равномерно и упорядочены по положению другого конца;
  вертикальные связи между рядами идут через коридор, а не вдоль границ блоков.
- Кратность подписывается снаружи блока со стороны входа.
- Маршрутизация и порты вынесены в общий `_routing.py` (диаграммы классов и объектов);
  диаграмма объектов тоже раскладывается по уровням владения.
- Ширина блока считается по реальной ширине текста (таблица ширин Helvetica, `_text.py`),
  а не по числу символов; размеры шрифтов — в `styles.yaml`.
- Палитра и размеры — в `styles.yaml` (`themes: dark | light`, `layout`);
  `build_xml(classes, theme=..., cfg_overrides=...)`. Линии стали видимыми на белом фоне.

### fragmos — блок-схемы из кода

**Новое**
- Режимы отображения: `plain` (текст как в коде), `default` (с «Ввод:/Вывод:»),
  `gost_19_701_90` (псевдокод по ГОСТ: `i = i + 1`, `≠ ≥ ≤`, `и/или/не`, границы цикла
  «Цикл i, …», без слов «Ввод/Вывод», `return X` — значение в параллелограмме).
- Стили текста задаются в `styles.yaml`: правила подписей, «Начало/Конец», «Да/Нет»,
  `return`/`break`/`continue` — без правки кода.
- Поддержка `do…while`, `break` и `continue` со стрелками к выходу / новой итерации цикла.
- Тернарники (`a if c else b`, `c ? a : b`) → ромб с двумя ветками.
- Python comprehension → цикл с накоплением результата.
- `match/case` с guard и несколькими паттернами; C# `switch` с `when` и fall-through
  (`case 1: case 2:` → `1 | 2`); C++ range-for с типом; C++17 `if (init; cond)`.
- Код уровня модуля (вне функций) — отдельная страница «Схема» с «Начало/Конец».
- Размер блока считается от текста с переносом по словам (старый режим `legacy` сохранён).
- Снятие префиксов строк в подписях (`f"…"`, `rf"…"`, C# `$"…"`).
- Юнит-тесты разбора и конвертации для Python, C++, C#.

**Изменено**
- Один «Конец» на функцию: каждый `return` ведёт к нему линией, а не создаёт свой терминатор.
- Прокладка линий по свободному месту: прямо вниз, если колонка свободна, иначе через
  коридор своей стороны; пересечения только там, где их нельзя избежать.
- Рендерер переписан в два прохода (раскладка → отрисовка); общий код генераторов
  вынесен в базовый класс; поля узлов извлекаются через tree-sitter Query — ошибка в
  имени поля ловится при импорте, а не теряется молча.

**Исправлено**
- `finally` выполнялся только в except-ветке — теперь на всех путях.
- `return` внутри `case` давал второй выход из блока.
- `break`/`continue` рисовались обычным блоком, после которого поток шёл дальше по циклу.
- `match` в режиме цепочки if терял `elif` и `default`.
- `case -1:` превращался в `== 1`; guard в `match` и тип в range-for терялись.
- Возвратная стрелка `for` делала «крючок»; стрелка `while` ложилась на родительский ромб.
- `std::cout` / `std::cin` не распознавались как ввод/вывод.
