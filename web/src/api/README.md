# `src/api` — как сайт разговаривает со службой

Один клиент на всё приложение. Экраны не зовут `fetch`, не думают про cookie,
про CSRF и про то, как выглядит отказ, — это всё сделано здесь один раз.

## Что откуда берётся

| Файл           | Зачем                                                                                                                                                   |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `schema.d.ts`  | Типы всех операций службы. **Сгенерирован**, править нельзя.                                                                                            |
| `client.ts`    | Клиент `api`, `unwrap()`, cookie + CSRF + 401.                                                                                                          |
| `errors.ts`    | `ApiError`, `errorText()`, `errorField()`.                                                                                                              |
| `types.ts`     | Формы ответов, которых нет в OpenAPI (`Me`, `Usage`, …).                                                                                                |
| `queryKeys.ts` | Ключи кэша TanStack Query.                                                                                                                              |
| `sse.ts`       | Чтение потоков `text/event-stream` с дочитыванием.                                                                                                      |
| `hooks/`       | Готовые хуки: `useBootstrap`, `useMe`, `useUpdateProfile`, `useModules`, `useUsage`, `useNotifications`, `useJobStream`, `useUserEvents`, `useIsAdmin`. |

Пересобрать клиент после правок службы:

    KORITSU_PYTHON=/путь/к/.venv/bin/python pnpm gen:api

Это снимает документ со службы **без её запуска** (`scripts/openapi-dump.py`
собирает `create_app(Settings.from_env())` на временном томе) и переписывает
`openapi.json` и `schema.d.ts`. Оба файла коммитятся: клиент обязан собираться
без питона.

## Запрос

```ts
import { api, unwrap } from '@/api'
import type { Project } from './types'

const projects = await unwrap<Project[]>(api.GET('/api/projects'))
```

`unwrap` бросает `ApiError` вместо возврата поля `error` — это то, чего ждёт
TanStack Query. Тип ответа задаётся параметром (`unwrap<Project[]>`), а не
выводится из схемы: половина обработчиков службы объявлена как `-> dict`, и
вывод дал бы `Record<string, unknown>`. Формы описывайте у себя —
`features/<область>/types.ts`.

Путь и метод проверяет компилятор: опечатка в адресе — ошибка сборки.

### Что клиент делает сам

- `credentials: 'include'` — cookie-сессия. Origin один и тот же (Vite
  проксирует `/api`), CORS не участвует;
- `X-CSRF-Token` на `POST`/`PUT`/`PATCH`/`DELETE` — значением cookie
  `koritsu_csrf`, которую служба выдаёт без `HttpOnly` именно для этого;
- `401` уводит на `/auth/login` (кроме `/api/auth/*`, где 401 значит «неверный
  пароль»).

## Ошибки

Служба отвечает `{"error": {code, message, where}}`, `message` — по-английски.
Показывать надо русский текст по `code`:

```ts
import { errorText, errorField, isApiError } from '@/api'

toast.error(errorText(e)) // «Неверная почта или пароль.»
errorField(e) // 'email' из where: 'body.email'
```

Русские тексты — `src/i18n/ru/errors.json`, ключ = код службы. **Новый код в
службе — новая строка там**, иначе человек увидит английское сообщение (это
запасной вариант, а не поломка).

## Запросы через TanStack Query

Ключи берутся из `queryKeys.ts`, а не пишутся строкой на месте: разошедшиеся
ключи не ломают сборку, они просто перестают сбрасывать друг друга, и человек
видит устаревшие данные без единой ошибки в консоли.

```ts
import { keys } from '@/api'

useQuery({ queryKey: keys.usage, queryFn: () => unwrap<Usage>(api.GET('/api/usage')) })
qc.invalidateQueries({ queryKey: keys.jobs.all })
```

Своей области — своё поле в `keys`. Файл дописывается, не переписывается.

Умолчания кэша (`app/queryClient.ts`): отказы 4xx не повторяются, изменяющие
запросы не повторяются никогда, перезапроса при возврате в окно нет.

## Потоки (SSE)

Два готовых хука. Оба переподключаются сами и продолжают с последнего события
(заголовок `Last-Event-ID`).

### Одно задание

```ts
const { events, job, done, status } = useJobStream(jobId)
```

- `events` — кадры `{seq, kind, data, at}` по порядку;
- `job` — карточка задания (`status`: `queued` | `running` | `done` | …);
- `done` — задание дошло до конца;
- `status` — состояние соединения: `connecting` | `open` | `reconnecting` |
  `closed` | `error`.

Хук сам отличает «задание кончилось» от «соединение оборвалось»: служба
закрывает поток в обоих случаях, поэтому после закрытия он перечитывает
карточку задания и переподключается, только если задание живо. На конце сбрасывает
`usage` — остаток месяца изменился.

Виды кадров (`kind`) задают обработчики службы, список открыт: разбирайте их
у себя.

### Поток человека

`useUserEvents()` открыт один раз в `AppShell`. **Второй раз его звать не
надо** — сколько вызовов, столько соединений. Он сам сбрасывает
`notifications`, `jobs`, `usage` и показывает тост на завершение задания —
целого прогона, а не куска: заполнение одного тега и разбор одного файла
человек видит на том самом месте, куда смотрит, и тост поверх этого сообщал бы
уже известное.

### Свой поток

```ts
const { frames, status, close } = useSseStream({
  url: '/api/что-нибудь/stream',
  onFrame: (f) => { … },
  shouldReconnect: () => true,
  keep: 0,          // не копить кадры в состоянии
})
```

Читается `fetch`'ем, а не `EventSource`: служба именует кадры (`event: <вид>`),
а `EventSource` отдаёт в `onmessage` только безымянные — половина потока
терялась бы молча.

## Загрузка страницы: один запрос вместо пяти

Оболочке для первого экрана нужно пять вещей: профиль, модули, расход,
пространства и колокольчик. Спрашиваются они **одним** ответом —
`GET /api/bootstrap` (`useBootstrap`), — а не пятью запросами, уходящими
одновременно с разных экранов.

Отдельные маршруты при этом остались и остаться обязаны: сводка нужна загрузке
страницы, а перечитать один расход после задания — это один расход, а не пять
ответов заново. Поэтому `useBootstrap` не подменяет чужие хуки, а **раскладывает
ответ по их ключам** (`setQueryData`): к моменту, когда `RequireAuth` пустит
экраны рисоваться, `useMe`, `useModules`, `useUsage`, `useWorkspaces` и
`useNotifications` читают из кэша и в сеть не идут.

Отсюда два правила для новых экранов:

- **свежесть назначается осознанно и подолгу там, где об изменении сообщает
  поток** (`useUserEvents` гасит `notifications`, `jobs`, `usage`; экраны гасят
  материалы и значения по концу задания). Нулевая свежесть означает не свежие
  данные, а лишний ответ на каждом переходе между экранами;
- **один список — один ключ.** Активные задания спрашивает общий
  `app/shell/useActiveJobs`, а не каждый желающий по-своему: два ключа с
  одинаковым содержимым — это два ответа службы и два разных числа на экране.

## Кто вошёл и права

```ts
const { data: me, isLoading } = useMe() // Me | null; null — не вошёл
const { isAdmin } = useIsAdmin() // boolean | undefined (профиль ещё едет)
```

`GET /api/auth/me` отвечает `{"user": {…}}`; обёртку снимает `useMe`, и снимать
её больше нигде не надо. `401` здесь не беда, а «не вошёл»: хук отдаёт `null`,
и защищённый маршрут уводит на вход сам (`app/guards.tsx`).

`nickname` — имя человека на экране: им подписаны приветствие на дашборде,
меню в шапке, участники пространства и личное пространство в переключателе. Почта рядом с ником показывается частично —
помощник `lib/maskEmail` (`a***@mail.ru`), и один он на весь сайт.

Свой профиль правится `useUpdateProfile()` (`PATCH /api/auth/me`): тело —
только те поля, что меняются, ответ кладётся в кэш `me` сразу. Отказы —
`invalid_nickname` (422) и `nickname_taken` (409), оба с `where: body.nickname`.

`is_admin` приезжает полем профиля. Правом оно не заведует: доступ решают
админские маршруты по колонке `users.is_admin` и белый список адресов на
прокси; поле нужно только затем, чтобы не рисовать страницу, за которую всё
равно откажут.
