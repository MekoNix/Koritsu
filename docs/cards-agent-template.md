# Шаблон: список вопросов → набор карточек

Готовый текст запроса для любой модели. Ему отдают список вопросов (к экзамену, к зачёту, к
семинару) — он возвращает файл набора в формате «Тренажёра», который остаётся сохранить как
`.json` и загрузить на странице «Тренажёр → Загрузить файл».

Полное описание формата — [`cards-format.md`](cards-format.md); шаблон повторяет из него ровно
то, что нужно модели, чтобы файл прочитался с первого раза.

## Шаблон

Скопируйте всё, что ниже, вместо `<<ВОПРОСЫ>>` вставьте свой список и отправьте модели.

```text
Переведи список вопросов в файл набора карточек. Ответь одним объектом JSON и ничем больше:
без пояснений до и после, без обёртки в блок кода и без комментариев внутри.

Формат ответа:

{
  "format": "koritsu.cards",
  "version": 1,
  "title": "<название набора>",
  "language": "ru",
  "cards": [
    {"topic": "<название темы>", "q": "<вопрос>", "a": "<ответ>", "note": "<разбор, необязательно>"}
  ]
}

Правила:

1. Одна карточка на один вопрос из списка, в том же порядке. Вопрос не сокращай и не
   переписывай без нужды; ответ пиши сам — короткий и точный, 1–5 предложений.
2. «topic» — название темы словами, как его показать человеку («Определённый интеграл»),
   а не идентификатор. Если список поделён на разделы, темой становится название раздела.
   Нет разделов — поле можно не писать.
3. «note» — разбор: типичная ошибка, поясняющий пример, мнемоника. Только там, где это
   правда помогает; пустых «note» не нужно.
4. Внутри "q", "a" и "note" разрешены: абзацы, **жирный**, *курсив*, моноширинный код,
   блоки кода, списки, таблицы, формулы KaTeX в долларах — $…$ внутри строки и $$…$$
   отдельной строкой. Запрещены: HTML (<br>, <div>), картинки ![](…), ссылки [текст](адрес)
   и голые https://…, команды \href, \url, \includegraphics.
5. Обратный слеш в JSON удваивается: пиши "\\int", "\\frac", "\\theta", "\\alpha", "\\,".
   Одиночный слеш ломает файл молча: "\theta" превращается в табуляцию и слово "heta".
   Перевод строки внутри строки — "\n", пустая строка между абзацами — "\n\n".
6. Только двойные кавычки; запятой после последнего элемента массива быть не должно.
7. Поле «id» не пиши — тренажёр проставит его сам.
8. Если вопрос непонятен или ответа нет в источнике, всё равно сделай карточку, а в «note»
   напиши, чего не хватает. Не выдумывай фактов, которых не знаешь.

Перед ответом проверь себя: объект начинается с «{» и заканчивается «}»; в «cards» столько
карточек, сколько вопросов в списке; у каждой непустые «q» и «a»; каждый обратный слеш
удвоен; ни одной ссылки и ни одной картинки.

Вопросы:

<<ВОПРОСЫ>>
```

## Как пользоваться

1. Вставьте шаблон в любую модель, на место `<<ВОПРОСЫ>>` — свой список (можно как есть, с
   нумерацией и заголовками разделов).
2. Ответ сохраните в файл с расширением `.json` — или просто скопируйте текст: на странице
   загрузки есть поле «Вставить текст».
3. «Тренажёр → Загрузить файл» → «Проверить». Превью покажет, сколько карточек годных, а у
   отклонённых назовёт место проблемы — карточку и поле.

Набор не обязан получиться с первого раза: исправить можно и в черновике, и в самом файле, а
потом загрузить снова. Если модель вернула текст вокруг JSON, лишнее достаточно удалить.

## Если модель ошиблась

| Что вернулось | Что скажет тренажёр | Как чинить |
|---|---|---|
| Текст или ``` вокруг объекта | Файл не читается как JSON, строка и столбец | Удалить всё до `{` и после `}` |
| `"\theta"` вместо `"\\theta"` | Карточка отклонена, `latex_escape` | Попросить удвоить слеши и прислать заново |
| `'q': 'текст'` | Битый JSON | Только двойные кавычки |
| `"topic": ["Предел"]` | Проблема поля, карточка отклонена | Тема — строка, а не список |
| Ссылка или картинка в ответе | Проблема карточки | Попросить описать словами или формулой |
| Карточек меньше, чем вопросов | Проблем нет, но набор неполный | Разбить список на части и отправить по частям |

Тот же шаблон лежит в интерфейсе: «Загрузить файл» → «Как устроен файл» → «Скопировать шаблон
для модели». Тексты держатся одинаковыми: `web/src/features/cards/agentTemplate.ts`.
